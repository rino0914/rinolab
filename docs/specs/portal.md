# 서비스 카드 추가 명세서

## 1. 개요

Rinolab 홈 화면에서 새로운 홈 서버 서비스로 이동할 수 있도록 서비스 카드를 추가한다.

## 2. 목적

- 사용자가 홈 화면에서 새 서비스의 용도와 이름을 확인할 수 있어야 한다.
- 사용자가 카드를 클릭해 해당 서비스로 이동할 수 있어야 한다.
- 기존 서비스 카드와 일관된 디자인 및 반응형 동작을 유지해야 한다.

## 3. 작업 범위

### 포함

- `portal/pages/dashboard.html`에 새 서비스 카드 추가
- 카드 제목, 설명 및 링크 설정
- 키보드와 모바일 환경에서 기존 카드와 동일하게 사용할 수 있는지 확인

### 제외

- 새 서비스 자체의 개발 및 배포
- 로그인 또는 접근 권한 처리
- 기존 서비스의 이름, 설명 및 URL 변경
- 전체 페이지 디자인 개편

## 4. 기능 요구사항

새 카드는 다음 정보를 표시한다.

| 항목 | 값 |
| --- | --- |
| 서비스 이름 | `Notes` |
| 설명 | `메모 관리` |
| 이동 URL | `https://notes.rinolab.org` |

사용자가 카드를 클릭하거나 키보드로 선택한 뒤 Enter 키를 누르면 지정된 URL로 이동해야 한다.

## 5. UI 요구사항

- 새 카드는 `.services` 영역의 기존 카드 다음에 배치한다.
- 기존 `.service-card` 클래스와 HTML 구조를 재사용한다.
- 별도의 인라인 스타일이나 중복 CSS를 추가하지 않는다.
- 화면 폭이 좁아지면 기존 CSS Grid 규칙에 따라 자연스럽게 줄바꿈되어야 한다.
- 기본 상태와 마우스 호버 상태의 모양은 기존 카드와 같아야 한다.

## 6. 구현 예시

```html
<a class="service-card" href="https://notes.rinolab.org">
    <h2>Notes</h2>
    <p>메모 관리</p>
</a>
```

구현 시 이 예시보다 프로젝트의 기존 코드 스타일을 우선한다.

## 7. 완료 조건

- 홈 화면에 `Notes` 카드가 표시된다.
- 카드에 `메모 관리` 설명이 표시된다.
- 카드를 선택하면 `https://notes.rinolab.org`로 이동한다.
- 기존 Drive, Photo, Console 카드의 내용과 동작이 유지된다.
- 데스크톱과 모바일 화면에서 카드가 겹치거나 화면 밖으로 넘치지 않는다.
- 브라우저 개발자 도구 콘솔에 새 오류가 발생하지 않는다.

## 8. 검증 방법

1. 브라우저에서 `portal/pages/dashboard.html`을 연다.
2. Notes 카드의 이름과 설명을 확인한다.
3. Notes 카드를 클릭해 이동 URL을 확인한다.
4. Tab 키로 카드에 포커스한 뒤 Enter 키로 이동할 수 있는지 확인한다.
5. 화면 너비를 모바일 크기로 줄여 카드 배치를 확인한다.
6. 기존 세 서비스 카드의 링크가 그대로인지 확인한다.

## 9. 미결 사항

- Notes 서비스의 실제 배포 여부와 URL 접근 가능 여부는 별도로 확인한다.
- 새 탭에서 열어야 한다면 구현 전에 `target="_blank"` 적용 여부를 결정한다.
